# ADR-0007 — Trust model: re-execution and git anchoring, not local record integrity

- Status: ACCEPTED
- Date: 2026-09-25
- Context: two independent reviews (reports/reviews/*os-pack*.md) showed that any record a local writer can create — evidence, review reports, gate history, finding histories — can be forged, and a secretless hash chain can be recomputed. Loop breaker: a third round of record validation would fail the same way.

## Decision
1. **Completion re-executes.** `lib/completion.mjs` never accepts a recorded PASS by itself. It re-runs each criterion's *declared* verify command (declared at `mission.mjs criterion --verify`), for every RESOLVED finding in mission scope the latest proof that runs one of its `requiredTests`, and every check of `gates/regression.json`, against the current workspace. A forged record cannot make a failing command pass.
2. **Proof and verify commands are allow-listed argv shapes** (`lib/commands.mjs`, parsed from argv[0], no substring matching): `node --test <existing test files>`, `node <existing integration/database test, OS probe or scripts/audit-db.mjs>`, an explicit set of npm test scripts (`NPM_PROOF`), `npx playwright test <existing browser specs>`; criteria may also use `npm run typecheck|build|lint|os:validate`.
   - An `env` prefix may only set allow-listed variables (`ALLOWED_ENV`: database/base-URL/browser settings); `NODE_OPTIONS`, `NODE_TEST_CONTEXT`, `PATH`, `npm_config_*` and `env` options are rejected.
   - Executed commands run with `NODE_TEST_CONTEXT`, `NODE_OPTIONS` and inherited `npm_config_*` removed, npm user/global config files disabled and `script-shell` pinned to `/bin/sh` (`childEnv`); `node`/`npm`/`npx` are resolved next to the running node binary (`resolveArgv`). `PATH` and `HOME` are inherited; other programs a script invokes are found on `PATH`.
   - A run that executed nothing is recorded FAIL (`ranNothing`): `# tests 0`, `# pass 0` (all skipped/todo), a node:test file-level pseudo-test (a file with no `test()` calls), Playwright "No tests found", or a direct `node --test` run without a positive `# tests N` summary.
   - Criteria are closed only by their declared command within their mission. A finding's proof must run one of its `requiredTests`: a named file must be an argument of the executed program, a named npm command must be the executed command (`matchesRequiredTests`, checked when entering REAUDITING/RESOLVED and again at completion). A finding with no parsable `requiredTests` entry cannot be verified (fails closed). A proof shows that suite passes; that the suite contains the regression test is checked by reviewers.
3. **Git anchors records.** From the commit that introduced this ADR on, every committed version of an evidence record must equal its first version, and every committed version of a finding must keep the previous version's history as a prefix (no new `reconstructed` entries) and its `requiredTests` as a subset (pack.mjs `gitAnchorErrors`); the working copy is checked against the last committed version the same way.
   - The mission definition (requirements, criteria, verify commands) is judged against the *first* commit carrying that mission id (`lib/mission-def.mjs`): later commits may add requirements/criteria but never change or remove them, `startedAt` must match the anchor and be neither later than it nor in the future, and the working copy must equal HEAD.
   - Mission scope (`missionFindingIds`, the single definition used by completion and the release gate) is: the listed findings, those with history since `startedAt`, and every finding file changed since the commit that closed the last *successful* mission (COMPLETED, verdict not D) — all findings when none exists. Aborting and restarting a mission therefore cannot shrink scope.
   - Limit: a hand-written COMPLETED entry in committed mission history would move the scope base; it is visible in the `state/mission.yml` diff. Deleting or rewriting commits requires rewriting git history, which the guard hook blocks for ordinary forms and a PR reviewer sees.
4. **Hash chain = tamper evidence for edits, not authenticity.** It detects accidental/edit-in-place changes and ordering breaks; it does not prove who wrote a record.
5. **Reviews are attestations bound to a ticket.** `dispatch.mjs` mints a ticket (role + workspace fingerprint + mission hash). A PASS review must quote it, match the role, match the current workspace and mission definition, and be single-use. The latest review of every role must not be FAIL, regardless of later edits. The OS cannot prove a report was written by an independent agent: reviewer authenticity rests on the operator's session and the pull-request review.
6. **The guard hook is a guardrail, not a sandbox.** It fails closed on unreadable input and parses common shell forms; quote concatenation, variable indirection, interpreters and other unusual constructs can still evade it. Server-side protection (branch protection, CI) remains the durable boundary.

## Consequences
- Browser and probe criteria run against a server started by the operator. For criteria that use Playwright, `test:browser`, an OS probe or an inline base URL, completion fails when `.next/BUILD_ID` is older than the last commit touching product paths (app, lib, modules, styles, public, assets, migrations, config, lockfile). Both timestamps are writer-controlled and the check does not prove the running process serves that build: rebuild and restart it from HEAD before running completion (the mission report records the build).
- The preview-workflow gate check is a structured text check (no YAML parser dependency): it decodes YAML escapes in double-quoted scalars, forbids `${{ }}` expressions, `secrets:` passing, non-plain quoted keys, shell constructs that set variables indirectly and redirections to variable targets in the public preview. It is a guardrail for review, not proof that no workflow edit can reach secrets.
- Completion is slower (it runs suites) and needs the environment those commands need (e.g. `DATABASE_URL`, a running server for browser criteria). Documentation must not claim more than this ADR.
